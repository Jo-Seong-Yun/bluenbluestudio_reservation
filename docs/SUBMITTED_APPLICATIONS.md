# 제출 당시 신청서 원본과 접수 우선 처리

## 배포 전 SQL

`supabase/migrations/20261103000100_submitted_applications.sql`을 SQL Editor에서 실행 확인한 뒤 master에 병합합니다. 아직 운영 DB에는 적용하지 않았습니다. CLI migration new는 `/home/agent/.supabase` EROFS로 실패하여 기존 마이그레이션 다음 번호를 사용했습니다.

## 정상 접수

- 신청서를 렌더링하는 서버가 고객에게 표시할 문항 정의·설명·옵션/가격·페이지/문구 구성·상품명/촬영시간/기본가를 서명합니다. 서버 전용 키의 HMAC으로 변조를 검증하며 고객 답변은 서명 토큰에 넣지 않습니다. 제출 때 토큰과 실제 답변으로 원본을 구성하므로 작성 중 관리자 편집이 있어도 양식이 바뀌지 않습니다. 가격은 서명된 당시 기본가·선택지 가격으로 서버 계산합니다.
- 기본 예약 RPC가 인적사항·신청 금액·희망 일정·접수를 먼저 저장하고 `submission_state=pending`을 남깁니다. 이후 원본 JSON 한 건을 reservation_submissions에 저장하고, 기존 업무 연동용 reservation_answers도 서버 권한으로 저장합니다. 모두 정상 완료되면 complete입니다.
- 원본에는 표시된 모든 문항의 답변 배열(빈 항목 포함)과 당시 정의, 제출 희망 일정과 예상 금액을 저장합니다. 과거 원본은 덮어쓰거나 수정하지 않습니다. 향후 새 문항도 같은 공통 경로를 사용합니다.

## 저장 오류의 예외 처리

- 필수 이름·연락처가 유효하면 일반 문항 검증 오류 때문에 접수를 막지 않습니다. 정상인 다른 인적사항과 문항 답변도 최대한 저장하고, 제출된 원문은 원본에 보관합니다. 금액은 허용된 옵션만으로 서버에서 계산하며 중복 전송된 옵션은 한 번만 셉니다.
- 원본/답변 저장 실패는 접수 성공을 취소하지 않습니다. complete / partial / failed와 오류 코드를 예약에 남기고, 상태 기록마저 실패해도 RPC의 pending 상태가 남아 관리자에게 확인이 필요한 것으로 보입니다. 저장 전 중단·필수 인적사항 불충분·예약 자체 DB 장애·유효하지 않은 희망 일정까지 접수를 성공했다고 표시하지는 않습니다.
- 토큰 유효기간은 24시간입니다. 오래 열어둔 탭/배포 전 탭/서명 검증 불가에서는 현재 서버 정의로 검증·저장하고 '제출 당시 양식 확인 불가'로 표시합니다. 현재 정의로 만든 자료를 당시 원본이라고 보증하지 않습니다.
- 원본 테이블은 FK가 없어 예약 삭제 이후에도 보존합니다. RLS로 익명 접근을 막고 인증 관리자 조회와 서버 INSERT만 허용합니다. UPDATE/DELETE/TRUNCATE는 권한 및 DB 트리거로 차단합니다. 원본 생성 메타데이터는 보존 이력에 기록하되 답변 원문은 통계 이력에 복제하지 않습니다.

## 관리자 열람

- 예약관리·예약내역의 공통 상세 패널에 접수 당시 원본 요약/신청 금액/읽기 전용 원본 링크를 표시합니다. 저장이 불완전하거나 pending이면 '추가 확인 필요'와 실패 항목을 표시합니다.
- 원본 페이지 `/admin/reservations/[id]/application`은 requireAdmin과 RLS로 보호합니다. 당시 질문·설명·선택지·가격·페이지 구성을 기존 고객 문항 컴포넌트로 렌더링하며 입력은 disabled입니다. 페이지 이동과 긴 설명 열람은 가능합니다.
- 기존 예약에 제출 당시 원본이 없으면 없는 것으로 안내합니다. 현재 편집 상태로 과거 신청서를 만들어 원본이라고 표시하지 않습니다. 기존 답변/예약의 업무 편집은 계속 가능하고, 제출 원본은 수정되지 않습니다.

## 박성준 예약 복구

예약 74NRDVWF의 동일 접수 시도에 속한 선택 이벤트를 접수 완료 시각 이전까지 대조했습니다. 기존 추가옵션 복구 외에 성별 남 / 본인입니다. / 스타일컷 변경 희망O / 영화 커뮤니티 / 개인정보 동의를 일반 답변 테이블에 복구했습니다. 이미 저장된 답변을 덮어쓰지 않았고 예약 상태·일정·금액을 변경하지 않았습니다. 할인코드·메모 원문은 확인할 근거가 없어 추정값을 쓰지 않았습니다. 이 예약의 당시 양식을 사후에 완전 재현했다고 주장하지 않습니다.
