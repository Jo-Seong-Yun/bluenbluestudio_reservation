# 삭제 후에도 남는 보존 이력

## 적용 전 필수 SQL

`supabase/migrations/20261102000100_permanent_audit_log.sql`을 Supabase SQL Editor에서 실행하고 성공을 확인한 다음 이 기능을 master에 병합합니다. AGENTS.md 규칙에 따라 실행 확인 전에는 배포하지 않습니다. CLI는 `/home/agent/.supabase` 읽기 전용 오류로 동작하지 않아 기존 마지막 마이그레이션 다음 번호를 사용했습니다.

## 수집 범위

- 고객: 기존 예약 이벤트(페이지·문항·선택·검증·실패·화면 상태), 기존 조회 기록, 실제 DB에 반영된 예약 생성/변경. 이벤트 ID 중복 재시도는 원본 upsert가 억제합니다.
- 관리자: 예약/상품/문항/고객/일정/운영시간/설정/이메일 규칙/발송 결과/비용/양식/원본 통계의 생성·변경·삭제, 로그인·로그아웃·관리 화면 진입. 로그인한 관리자의 고객 예약 화면 테스트도 별도 보존합니다.
- 위 도메인의 18개 기존 테이블에 INSERT/UPDATE/DELETE 트리거를 설치합니다. 실제 변경이 없는 UPDATE와 통계 마지막 열람 시각만 바뀐 UPDATE는 생략합니다. 새 테이블을 추가할 때에는 이 마이그레이션의 `preserve_audit_history` 트리거도 설치해야 합니다.
- 예약/상품 삭제의 FK CASCADE 및 SET NULL이 원본 이벤트를 변경해도 원래 보존본은 FK가 없어 남습니다. 원본 로그 삭제, 메모 수정, 통계 초기화 자체도 새 변경 기록으로 남습니다. 성과 집계는 기존 원본을 사용하여 삭제된 예약·관리자 테스트가 유효 고객 전환으로 남지 않게 합니다.

## 확인할 수 있는 것

`/admin/analytics`의 **전체 보존 이력 보기** → `/admin/analytics/audit`. KST 시간별/밀리초, 작업자, 생성·변경·삭제, 태그·대상 ID·세션·상품 필터, 변경 전/후 허용된 값과 변경된 항목 이름, 100건 커서 이어 보기. 삭제된 대상도 원본 ID/예약번호/상태/금액으로 확인합니다. 작업자 UUID는 검증된 인증에서 얻고 브라우저 입력값으로 받지 않습니다. 기존 이관분의 작업자는 추정하지 않고 '주체 미확인'으로 표시합니다.

## 보존·보안과 한계

- `audit_logs`는 RLS, 인증 관리자 SELECT, 서버 INSERT만 허용합니다. UPDATE/DELETE/TRUNCATE는 DB 트리거로도 차단합니다. UI에 수정·삭제 버튼이 없습니다. DB 소유자가 직접 트리거를 해제하는 행위까지 막는 외부 불변 저장소는 아닙니다.
- 상태·금액·ID·이벤트 메타데이터만 allowlist로 복제합니다. 고객 이름·전화·이메일·생년월일·답변 원문·메모·발송 본문·비밀번호·설정의 자격증명은 보존 이력에 복제하지 않습니다. 어떤 민감 필드가 변경됐는지는 필드명으로만 남습니다.
- 트리거 이력은 원본 변경과 같은 트랜잭션이므로 둘 중 하나만 반영되지 않습니다. 이력 저장이 실패하면 해당 DB 변경도 롤백됩니다. 롤백된 관리자 DB 작업의 오류 원문은 여기 남지 않습니다. 고객 오류는 기존 클라이언트의 검증/제출 오류 이벤트로 보관합니다.
- 로그인/로그아웃/화면 진입은 별도 서버 호출로 best-effort 수집합니다. 관리자 경로는 정적 섹션명만 남겨 쿼리/식별정보 유출을 막습니다. 브라우저 차단·종료·네트워크 실패로 서버에 도달하지 않은 행동을 완전 수집한다고 보장하지 않습니다. 인증 공급자 자체의 실패 로그·DB DDL·파일 시스템/스토리지 변경·모든 DOM 클릭을 수집하는 기능은 아닙니다.
- 트리거 설치와 현재 남아있는 데이터의 일회성 이관을 잠금/단일 트랜잭션으로 처리합니다. 재실행해도 이관을 중복하지 않습니다. 이미 지워진 과거 데이터는 복구하지 않습니다. 자동 보존기간 삭제는 추가하지 않았으므로 증가량/DB 용량을 운영 중 확인해야 합니다.

## 검증

로컬 PGlite PostgreSQL에서 SQL 재실행, 기존 자료 이관, 관리자 UUID, 예약 상태 변경 전후, 예약/상품 cascade, 접수 이벤트 보존, 개인정보 allowlist, UPDATE/DELETE/TRUNCATE 차단, anon 접근 거절, authenticated 읽기 전용, 트랜잭션 롤백을 검증했습니다. 실제 타임라인 컴포넌트의 KST/삭제 스냅샷/hidden 표기/모바일/조회 실패 후 기존 이력 유지를 확인했습니다. 자료 `/workspace/.reviews/permanent-audit/`. 운영 DB 쓰기나 테스트 예약/메일은 실행하지 않았습니다.
